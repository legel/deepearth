# Biological Scorecard — what the numbers mean

> **The numbers live in [`scorecard.txt`](scorecard.txt)**, generated by
> `harness/board.py::write_scorecard` after every run and committed to git, so anyone can read the
> campaign's state without the gitignored board. **Never hand-edit it** — a hand-maintained scorecard
> drifts, and a drifted one is worse than none. This file explains what each row means, how a record is
> earned, and what is excluded and why. The index of all loops' scorecards is
> [`../../../scorecard.md`](../../../scorecard.md).
>
> **This loop has no records yet.** Everything before protocol `v1-nulltree` was measured by a probe
> that printed numbers and stored nothing — no identity, no fair control, no gate, no board. Those
> numbers are not records and cannot be migrated; the first run under `v1-nulltree` establishes each
> row's baseline.

## What `v1-nulltree` measures

The claim under test is narrow and specific (science.md rules 7, 8, 29):

> the **real dated phylogeny's** topology and branch lengths carry biology the seed does not.

So the score is not "does the graph help". It is "does the graph help *because the tree is the actual
phylogeny*". Three rules define a score:

| rule | why it exists |
|---|---|
| the fair control is a **null tree**, not the seed | a control must differ from the encoder in ONE thing — see below |
| the control is the **strongest** member of its family | a gain that only survives the weakest null is not a gain |
| the encoder's share is measured against **contested headroom** | the seed is inherited by both arms and neither can earn it |

### The fair control, and why `vs seed` is not one

`bio_gain` was `graph(ON) − graph._seed()` for this loop's whole history. That is an **ablation**: it
confounds the tree with the parameter count, the training loop and the reconstruction objective all at
once. It looked like a hard bar only by accident of this dataset — the E1 text prior already scores
~0.89 family-NN unaided, so almost anything looks weak beside it. Swap in the vision seed (~0.47) and
`vs seed` is beatable by any neighbourhood smoothing at all; a plain k-NN average would "win".

The control holds the seed, `d_model`, layers, heads, **parameter count**, the rule-25 mask protocol,
the budget, the split and the readout all fixed, and deletes only the *realness* of the tree
([`../harness/nulltree.py`](../harness/nulltree.py)):

| member | what it falsifies |
|---|---|
| `null-tree/perm0…4` | the identical tree buffers with the species→leaf assignment permuted. Topology, branch lengths and node count are byte-identical; only clade membership stops meaning relatedness. The standard tip-shuffle phylogenetic-signal null. |
| `null-tree/seed-dendrogram` | an average-linkage ultrametric built from **seed cosine**. Asks whether the dated phylogeny beats a tree the seed could have drawn by itself. If E1 is phylogeny-derived, this is the member that will say so. |

`null-tree/best` is the **maximum** over the family — generous to the control by design, exactly as the
spacetime loop's RFF control keeps its best bandwidth. `FAIR_ORDER = ["vs null-tree"]`, one entry, for
the same reason that loop collapsed its own to one: a preference list over several labels is how three
different quantities came to share a single column of a board.

`vs seed` is still reported next to it. It is not fair and cannot set a record.

## Reading a row

```
capability              record  fair-gain  read              runs  seeds  protocol
family_from_phylo       0.9012  +0.0031    ENCODER-LIMITED   14    2s     v1-nulltree
```

- **record** — the absolute score in the row's own metric (`primary`), the mean across seeds, never the
  max of reruns.
- **fair-gain** — `record − null-tree/best`. Negative is a real and useful result.
- **read** — which lever the measurement points at:

| read | means | lever |
|---|---|---|
| `OPERATOR-INERT` | the graph moved nothing over its own seed (`refined_seed_norm ≈ 0`) | ARCHITECTURE — the operator is not engaging |
| `INPUT-LIMITED` | loses to a tree of the same shape carrying no phylogeny | DATA — change the seed (rule 26) or the target |
| `ENCODER-LIMITED` | wins, but <25% of the contested headroom | ARCHITECTURE — change the operator |
| `EARNING` | ≥25% of the contested headroom is the real tree | push the mechanism |

**Why "contested headroom" and not the score.** The share is
`fair_gain / (record − seed)`, not `fair_gain / record`. Family-NN accuracy is ~0.89 here and nearly
all of it is the frozen text prior, which the real tree and every null tree inherit *identically*. The
most the operator can contest is ~0.11, so a plain `fair/record` ratio caps the share at ~12% and would
stamp every biological row `ENCODER-LIMITED` however good the operator was — the same failure as the
old absolute `primary < 0.20` rule, re-entering through the denominator. The spacetime loop passes
`floor=0` because its head sees only encoder features; the shared code is one function either way.

## Layer 2 — declared and refused

| capability | why it cannot be probed here |
|---|---|
| `pollinator_from_species` | not separable from `pollinator_transfer` under this probe, and the probe has no env channel. The only readout of a plant's pollinator set is the held-out-plant reconstruction, which *is* transfer-from-relatives; the unmasked variant scores a plant whose own identity trained the bilinear head. Its benchmark B41 is "plant identity + env → pollinators", and env is exactly what a standalone species-level probe lacks. |

The reasons are the ones in `harness/board.py::EXCLUDED_CAPABILITIES`, and the audit checks that every
mapped capability is either produced by a `declare()` site or refused there with a reason.

## Known limits of the current protocol

- **The split is `species-random`.** A held-out species' congeners stay in TRAIN, so on a family-NN
  metric much of the seed's ~0.89 is close to memorizing the sister species. The biological analogue of
  the spacetime spatiotemporal-block split is to hold out whole genera or families; that is
  `v2-cladeblock` on the roadmap and it will re-baseline every row. Declaring `species-random` now is
  what makes that change legible as a re-baseline rather than an unexplained drop.
- **The FungalRoot mycorrhiza label is a per-genus majority**, so a nearest congener predicts it almost
  trivially. This is precisely what the null trees neutralize: a permuted tree cannot exploit
  congenery, so what survives in the fair gain is not the genus shortcut.
- **`--no_control` runs are diagnostic.** They skip the null family, so they have no fair gain and can
  never set a record. They are a legitimate fast screen; they are not evidence.
