# spacetime — Earth4D encoder loop

```
  program/            the contract. Read first; change only when doctrine changes.
  harness.py          THE JUDGE — runs the probe, gates the record, writes the ledger. Not editable to win.
  editable_files/     THE ONLY CODE AN EXPERIMENT MAY EDIT
  records/            board, traces, ledgers. Never hand-edited.
```

| `program/scorecard.md` | what each row means, and what is excluded and why | pick your metric here |

Scoring is **not** here. `net_value`, `noise_barrier`, `signal_capture`, `science_axes` and the metric
registry live in `autoresearch/scoring/definitions.py`, outside every `editable_files/`, because what a
number means must not be editable by the experiments it judges.

## What is measured — protocol v5-encoder-only

```
   encoder   Earth4D(spatial_levels=18, temporal_levels=18, log2_hashmap=20,
                     freq_log_scale_init=-2.5)     = 36 spatial + 108 tri-plane = 144 dims
   control   RFF at FAIR_CONTROL_DIM = 144         matched width
   protocol  train_encoder=True, EARTH4D_DETERMINISTIC=1, 800 steps per arm
   gain      "vs RFF" — the same quantity on all six capabilities
```

This is exactly what `fusion.py:302` instantiates, so a probe number is about the object fusion runs.
Before v5 it was not: the head received 20,663 features and the hash grid was 36 of them (0.17%), the
rest tile coding and a fixed RFF. **Every pre-v5 record measured something else.**

The bolt-on bases (`fourier`, `time_harmonics`, `spatial_cline`, `nystrom`, `tile*`) still exist and all
default OFF. Turning one on measures the encoder *plus* that basis, and the record must say so.

## An experiment is an edit on a branch

Not a new file, not a new flag. `git worktree add ../e4d-<tag> -b exp/<tag>`, edit `CONFIG` in
`probe.py` or `earth4d.py` in place, sweep, and let the branch hold the isolation. A dead lever is a bug.
Gating at conception instead is what produced 113 flags, a 1,552-line `main()`, 21 `champion_*.yaml`
variants and a pile of `diag*.py` copies — and cost every later agent the reading.

## Running

```bash
# where do I edit to move this capability?
python -m deepearth.autoresearch.scoring.definitions --capability family_from_spacetime

# one experiment, recorded
EARTH4D_DETERMINISTIC=1 python -m deepearth.autoresearch.probes.spacetime.harness \
    --metric family_from_spacetime --tag my_swing --device cuda:0 --ensue

# five matched seeds — required before a record becomes a claim
EARTH4D_DETERMINISTIC=1 python -m deepearth.autoresearch.probes.spacetime.harness \
    --metric family_from_spacetime --tag my_swing_5s --seeds 5 --device cuda:0 --ensue

# is the backward reproducible on this build?
python -m deepearth.autoresearch.probes.spacetime.harness --determinism

# which science.md rules have an instrument, and which do not
python -m deepearth.autoresearch.scoring.definitions --coverage
```

The CLI carries only what decides **which measurement** is being made — capability, seed, device, result
path. Every lever lives in `CONFIG`, and `config_digest` puts it in the record's identity, so two runs
with identical command lines but different `CONFIG` are never treated as the same measurement.

## Known gaps

- **rule 24** (dense 4D field, sampling between observations) — unmeasured. `run_field_decode` exists and
  has no caller. This is the axis that would have scored `drop_spatiotemporal` and CMAC tile coding as
  regressions instead of records.
- **rule 2b** (relative encoder) — unmeasured here. `encode_relative` exists and `fusion.py:54` calls it;
  the probe never calls it.
- **rule 1** (causal autoregression) — unmeasured. The split is past→future, but nothing consumes
  observed state and rolls its own predictions forward.

`scoring.definitions --coverage` is the live list.
