# ─────────────────────────────────────────────────────────────────────────────────────────
# On replacing richdem
# ─────────────────────────────────────────────────────────────────────────────────────────
# WhiteboxTools (`pip install whitebox`) installs as a precompiled binary on Python 3.11 and
# offers breach_depressions_least_cost by the same author as the algorithm richdem
# implements, so it looks like a clean substitute. It was measured, and it is not:
#
#   Conditioning the same DEM, then routing both with pysheds:
#     richdem vs itself          flow-dir 100.00% identical, stream IoU 1.0000  (deterministic)
#     richdem vs whitebox        flow-dir  87.87% identical, stream IoU 0.2875
#     richdem vs unconditioned   flow-dir  81.24% identical, stream IoU 0.2223
#
# Elevations agree within 1 mm on 98.3% of cells, but that is not the product. This AOI has
# ~14 m of relief over 2 km, and on terrain that flat D8 routing is decided by sub-millimetre
# differences at pits and flats — so two legitimate breaching algorithms produce substantially
# different stream networks. Swapping would silently rewrite every stream network, watershed
# and HAND surface, and invalidate the Gee Creek gauge validation, which was done with richdem.
#
# Worth noting on its own terms: an IoU of 0.29 between two defensible algorithms means the
# delineated stream network carries far more uncertainty than it is usually treated as having.
# That is relevant to this project's documented D8 under-capture at Gee Creek (11.65 of
# 33.15 km²), which may be less about missing wetland connectivity than it appears.
