You are running the **Earth4D space-time probe loop**. Your entire surface is
`autoresearch/probes/spacetime/`. That directory is self-contained by design — its program, its
harness, its probe, its encoder, its records and its tests are all inside it. You do not need, and must
not touch, anything outside it.

## Before anything else

1. Read `autoresearch/probes/spacetime/program/program.md` — the loop, the levers, the evidence
   standard, the experiment-tracking rules. It is binding.
2. Read `autoresearch/probes/spacetime/program/scorecard.txt` — the current board, generated by the
   harness. Never hand-edit it.
3. Read the Ensue key `LOOP-earth4d-<metric>` and the capability's `deadends` in
   `autoresearch/probes/spacetime/records/records.json`. **Skip anything already logged.** Re-running a
   published dead-end is the single most wasteful thing you can do.

## The declared metric

$ARGUMENTS

If no metric is given, use the one already declared in the most recent Ensue entry. **Do not switch
metrics.** The operator selects the metric from the scorecard; drifting to an easier capability after a
failure is the exact deviation `--metric` exists to prevent. If you believe the metric is wrong, say so
and stop — do not change it yourself.

## One cycle

```
① READ    board + Ensue dead-ends
② DIAGNOSE  read the BOTTLENECK line: share = fair-gain / score
              INPUT-LIMITED (gain ≤ 0)      → DATA lever, change the channel
              ENCODER-LIMITED (share < 25%) → ARCHITECTURE lever, change the mechanism
              EARNING (share ≥ 25%)         → the mechanism carries signal, push it further
③ HYPOTHESIZE  one change, stated as a falsifiable claim before you run it
④ EDIT      git worktree add ../e4d-<tag> -b exp/<tag>; edit earth4d.py / probe.py IN PLACE
⑤ RUN       ONE seed, through the harness, on the box — always, no exceptions
⑥ DECIDE    the harness applies the noise barrier — do not argue with it
⑦ PUBLISH   --ensue on EVERY run, win or dead-end, with its bottleneck reason
```

## Hard rules

- **An experiment is an EDIT on a BRANCH. There are no flags to try an idea with.** The probe's CLI is
  four arguments — capability, seed, device, result-json — and every lever lives in the `CONFIG` block
  at the top of `probe.py`. Change CONFIG, or change `earth4d.py`, commit on a branch, run. Do not add a
  flag. Do not copy a file. `config_digest` puts what you built into the measurement identity, so a
  rewired encoder is never compared against the control as the same measurement.
- **CONFIG starts at the standing champion**, so a run with no edits reproduces the record. If your run
  scores wildly differently before you have changed anything, you have changed the measurement, not the
  result — check what you edited.
- **Screen at ONE seed. Go broad.** GPU is precious and the goal is breakthroughs, so spend it on many
  different hypotheses, not on measuring one hypothesis five times. The noise barrier already refuses
  noise — that is its job — so a screening run needs no repeats. Flat at one seed IS your answer:
  publish the dead-end and move to the next idea.
- **NEVER run `--seeds`. One seed, always.** The barrier is the filter. Clears it → record. Doesn't →
  dead-end, publish, next idea. No confirmation runs, no re-running to be sure, no escalation. Every
  second of GPU goes to a NEW hypothesis; re-measuring one you already have discovers nothing.
- **Never edit `editable_files/harness.py` to make a run look better.** It decides what a number
  means. If the harness is genuinely wrong, fix it as its own commit with a test that fails before and
  passes after, and say so explicitly — never inside an experiment.
- **Never hand-edit `records/`.** The harness writes it. A correction goes through the ledger with its
  reason.
- **Publish dead-ends.** A failed lever is information the swarm paid for. Losing it means someone
  re-buys it. Publishing means **Ensue**, not the git remote.
- **Never `git push`.** This is a shared repository. Commit every run to your LOCAL branch — failures
  included — and report the local commit SHA. An experiment branch, especially a failed one, does not
  belong on the remote. If you think something has earned the main line, say so and let the operator
  decide; pushing is never your call.
- **Do not claim a ceiling.** N failed levers is evidence about those N levers. Where the ceiling is,
  is the thing being discovered.
- **Report honestly.** If a run failed, say so with the output. If a result is inside the noise, say
  "inside the noise", not "a slight improvement".

## Running on the box

```bash
ssh newbox                                   # connection details: program/box-operations.md
cd /workspace/deepearth && export PYTHONPATH=/workspace

# what can move this capability, and where do I edit?
python3.12 -m deepearth.autoresearch.probes.spacetime.editable_files.harness \
    --list-modes --capability <metric>

# SCREEN one idea (default 1 seed). The experiment is your CONFIG / earth4d.py diff, not a flag.
python3.12 -m deepearth.autoresearch.probes.spacetime.editable_files.harness \
    --metric <metric> --tag <tag> --device cuda:0 --ensue



# measure WITHOUT recording (parity checks, smoke tests)
EARTH4D_ALLOW_UNRECORDED=1 python3.12 -m deepearth.autoresearch.probes.spacetime.editable_files.probe \
    --capability <metric> --seed 0 --device cuda:0 --result-json /tmp/r.json
```

**Work in your OWN worktree, and point PYTHONPATH at it.** Several agents share this box. If you edit
`/workspace/deepearth` directly you are changing the tree everyone else is measuring in, and their
numbers become yours.

```bash
git worktree add /workspace/<yours>/deepearth -b exp/<tag>     # NOT /workspace/deepearth
cd /workspace/<yours>/deepearth
PYTHONPATH=/workspace/<yours> python3.12 -m deepearth.autoresearch...   # NOT /workspace
```

`PYTHONPATH=/workspace` resolves `deepearth.` to the SHARED checkout, so a worktree run with it executes
somebody else's code and not your edit. That has already silently invalidated arms twice tonight — once
where a whole batch ran against another agent's tree, and once where a published dead-end carried a
number measured through someone else's config.

Both GPUs are usable; check `nvidia-smi --query-compute-apps=pid,used_memory --format=csv,noheader`
first. Disk is shared and finite — never `cp` the corpus, and clean up `/tmp` after yourself.

## What to report back

The hypothesis, the arms you screened with their scores, the barrier they had to clear, whether each
cleared it, and what you published. One paragraph. If nothing cleared the
barrier, that is a complete and useful answer — say it plainly and state what you ruled out.
